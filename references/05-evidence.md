# 阶段五：证据规范、用例格式与动态验证门禁

## 1. 三类证据，结论必须归类

| 类别 | 定义 | 报告标注 | 允许的措辞 |
|---|---|---|---|
| ① 已实测 | 在授权隔离环境跑过，有输出/日志/截图 | `[实测]` | "已复现""实测确认" |
| ② 代码可证 | 静态代码事实 + file:line，无需运行即可判定 | `[代码]` | "代码中不存在 X""逻辑必然导致 Y" |
| ③ 待验证 | 依赖环境、版本、配置或运行时才能确认 | `[待验证]` | "疑似""需在隔离环境验证" |

禁止把 ③ 写成 ①。报告开头给一张统计表：P0–P3 各多少条、其中实测/代码/待验证各多少。

## 2. 用例字段（逐条填写，不许空）

```markdown
### TC-AUTH-004 普通用户调用管理端订单列表

- 关联接口：GET /api/admin/orders
- 目标：验证功能级授权在服务端生效
- 前置：普通用户 token；测试库有 ≥1 条订单
- 步骤：携带 user token 请求，无 role 头；再重复一次带 `X-Role: admin`
- 预期：401/403，响应不含订单数据
- 实际：200，返回 20 条订单（evidence/E-TC-AUTH-004-20260101.log）
- 判定：FAIL
- 风险级：P0
```

判定值：`PASS` / `FAIL` / `BLOCKED`（环境不具备）/ `NOT RUN`（本轮未执行，需授权或未纳入范围）。BLOCKED 与 NOT RUN 必须写原因。

## 3. 动态测试门禁（全部满足才执行）

- [ ] 目标为测试/隔离环境，非生产域名、非生产库
- [ ] DB 账号只读，或测试库可在测试后重置
- [ ] 支付为 Mock/沙箱，不产生真实资金流
- [ ] 测试数据独立（专用手机号/用户/订单），事后可清理
- [ ] 压测有上限（QPS/并发/时长），且不与他人共享环境冲突
- [ ] 安全测试限于非破坏性（不做删库、爆破、拒绝服务、真实注入写操作）
- [ ] 用户已明确授权（记录授权原话与时间）
- [ ] 有停止开关与回滚步骤

任一不满足 → 只交付计划与可执行命令，标明"未执行"。

## 4. 执行顺序（静态 → 动态）

1. 静态清点（阶段 1）
2. 风险清单 + 用例设计（不改代码）
3. 环境与数据确认（门禁）
4. 只读动态验证：单次请求、越权探测、幂等重放、EXPLAIN
5. 有授权再做并发与压测
6. 记录真实结果，失败也记录（失败是证据）

## 5. 证据文件规范

```
evidence/
├── E-TC-AUTH-004-20260101T101500.log     # 请求/响应（token 已掩码）
├── E-SQL-002-explain.txt                 # EXPLAIN 输出
├── E-CODE-007-order.service.ts-118.txt   # 代码摘录（含行号）
└── E-PERF-001-k6-summary.json            # 压测摘要
```

命名：`E-<用例ID>-<时间戳>.<ext>`。日志中必须掩码：`Authorization`、`Cookie`、`session_key`、`AppSecret`、手机号中间四位、身份证、银行卡。保留请求方法、URL、状态码、耗时、响应摘要，去掉完整响应体中的隐私字段。

## 6. 常见误报（交付前自查）

| 误报 | 先确认什么 |
|---|---|
| "SQL 注入" | 是否 ORM 参数化；是否只是变量名看起来危险 |
| "越权" | 是否有全局中间件按登录身份注入 userId（读中间件源码） |
| "未鉴权" | 鉴权是否在网关/反代层统一做 |
| "并发重复" | 是否有唯一索引（重复会报错而非脏数据，级别需下调） |
| "XSS" | 框架是否默认转义；是否只在管理端内部使用 |
| "敏感信息泄露" | 字段是否仅返回本人数据 |
| "性能差" | 数据量、缓存、索引是否已知；无数据时只能写"风险" |
| "缺事务" | 是否单表单行写，本身无需事务 |

## 7. 证据强度对照

| 结论类型 | 最低证据 |
|---|---|
| 接口不存在鉴权 | 路由注册代码 + 全仓搜索中间件无结果 |
| 金额可篡改 | 客户端入参进入计价函数的代码路径 |
| 回调未验签 | 通知处理函数全文 + 无验签调用 |
| 竞态导致重复履约 | 状态更新语句无状态条件 + 无唯一约束 |
| 慢查询 | EXPLAIN 的 type/rows/Extra + 表数据量 |
| 越权实测 | 两个账号的请求与响应原文 |

## 8. 工具选择（只读优先，安装需授权）

| 目的 | 栈 | 工具 | 说明 |
|---|---|---|---|
| 接口测试 | Python / Node / Java | pytest+httpx / Jest+Supertest / JUnit+MockMvc | 复用项目现有测试栈，别新引框架 |
| 静态安全扫描 | 多语言 | Semgrep（`semgrep --config=auto`）、bandit、gosec、npm audit | 只读跑，不改依赖；结果需人工确认误报 |
| 依赖漏洞 | Node / Python / Java | `npm audit --json`、`pip-audit`、`mvn dependency-check` | 记录版本与 CVE，不自动升级 |
| SQL 计划 | MySQL / PG | `EXPLAIN`、`EXPLAIN ANALYZE`、`pg_stat_statements` | 只读账号执行 |
| 压测 | 通用 | k6、Locust、wrk、hey | 先计划后授权；目标必须是测试环境 |
| 动态 Web 扫描 | Web | OWASP ZAP（被动模式） | 仅授权环境，主动扫描需单独批准 |
| 性能剖析 | Node / Python | `--prof`、clinic、py-spy、cProfile | 观察生产需另行授权 |

执行任何扫描前确认：不写目标、不带真实凭据、结果文件落在 `evidence/`。

## 9. 完成判据

- [ ] 每条问题都带 ①/②/③ 标签
- [ ] 每个 FAIL 有证据文件路径
- [ ] BLOCKED/NOT RUN 写明原因与所需条件
- [ ] 证据中无明文凭据与隐私
- [ ] 有"测试环境与授权记录"小节
